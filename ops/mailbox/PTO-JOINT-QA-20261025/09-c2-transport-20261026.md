# C2 — транспортная таблица т·км в XLSX import

## Итог

Проверка выполнена только на синтетическом XLSX, созданном в памяти и пропущенном через production `readXlsx` и native LRV tree builder. Реальной книги для проверки не предоставляли; вывод о ее точном формате и фактическом дефекте остаётся UNKNOWN.

Для проверенной формы обнаружены два разных исхода:

1. Если книга содержит распознанный LRV и отдельный лист транспорта, транспортный лист получает `nomalum` и при автотегировании исключается из списка LRV. Дерево строится только из LRV. Это означает, что транспортные строки и их т·км не попадают в canonical tree этого импорта.
2. Если книга состоит только из транспортного листа, автотегирование также получает `nomalum`, но fallback принудительно помечает первый лист как LRV. В синтетическом примере две нумерованные транспортные строки превращаются в `RS` под сгенерированным RZ `Асосий бўлим`. Количество, цена и сумма попали в узлы; расстояние и грузооборот (т·км) отсутствуют в tree. Значит, для этой формы данные не исчезают целиком, но транспортная семантика и т·км теряются при преобразовании.

Пустой RZ этим воспроизведением не подтверждён. Если дерево действительно пусто, native upload останавливает импорт с явной ошибкой на `SmetaYuklaNative.tsx:1622–1624`; тихого успешного пустого дерева в этой ветке нет. Также не подтверждено, что все реальные transport-таблицы имеют проверенную структуру.

## Ограниченное предложение по исправлению

В ветке fallback не назначать первый лист LRV, когда структурный classifier распознал его как transport/svod. Оставить лист невыбранным и потребовать явного решения оператора; сохранить существующий ручной выбор. Для transport-only формы отдельный follow-up должен определить поддерживаемый контракт т·км и показать поля в preview/review до включения этих значений в canonical model. Не выводить т·км из количества, расстояния, цены или суммы.

Границы: предложение касается только автотега первого листа и проверки транспортной модели. В этой задаче runtime-код не менялся. Не менять общую семантику импорта, LRV/RES, схему БД или правила расчёта.
