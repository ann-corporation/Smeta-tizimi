# K2 — metadata / private R2 (source only)

Миграция `20261203001100_t2_normativ_v1.sql`, acceptance BEGIN…ROLLBACK / `T2_NORMATIV_V1_ACCEPTANCE_PASS`, rollback с nonempty guard.
Новые таблицы: global `t2_normativ_hujjat` + `t2_normativ_bolak`; generated FTS/trigram только по metadata labels/codes, не по полному тексту.
RLS включён, anon/authenticated не имеют прямых прав. Service-role BFF вызывает только named RPC с server-derived actor:
`t2_normativ_hujjat_qosh_v1`, `t2_normativ_holat_v1`, `t2_normativ_oqi_v1`.
Текущая DB-суперадминская роль разрешает запись/review; активный member указанной активной компании читает общие PUBLISHED записи.
Нет подмены custom cookie auth на auth.uid(); до K3 новые RPC не подключены к публичному HTTP gateway.

Последняя команда — offline dry run: без SDK, env credentials, R2 и DB записи.
Только L0 после review/миграции: установить `requirements-r2.txt`, задать R2_ACCOUNT_ID/AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY/R2_BUCKET,
SUPABASE_URL/SUPABASE_SERVICE_ROLE_KEY в env и добавить `--apply --actor <DB-superadmin-id>`; secrets не передавать в argv/лог.
Ключи R2 content addressed: original/SHA, derived/SHA, chunks/fileSHA.json, manifests/jobSHA.json. Полные chunks с текстом/bbox остаются только в private R2.
Immutable conditional PUT IfNoneMatch=*,412 допускается только при совпадении SHA metadata и длины; несовпадение закрывает upload.
RPC регистрации metadata вызывается после всех uploads. Частичный upload может оставить immutable orphan objects, но не частичную DB-регистрацию.
Manifest содержит исходный K1 job для проверки reader/config identity. SQL metadata никогда не содержит matn; неизвестные page/table остаются NULL.
Операция регистрации UUID5(jobSHA+actor) повторяема, immutable input conflict не перезаписывает издание.
ZIP-root с дочерними jobs загружается по одному child job с соответствующим исходным member-файлом; автоматического разворачивания ZIP uploader нет.

Нечитаемый DOC без конвертера сохраняет original/REVIEW metadata без chunks; OCR_REQUIRED/low-confidence и другие неустранённые extraction flags блокируют INDEXED/PUBLISHED.
Ручное подтверждение jobSHA + CAS версии переводит REVIEW→INDEXED→PUBLISHED; reviewer/actor/operation зафиксированы, прямой skip запрещён.
Semantic/image/footnote/nested/tracked-change review flags снимаются только явным admin подтверждением; extraction/code/edition conflicts не снимаются автоматически.
Реальное применение SQL, R2 upload, OCR и production login здесь не выполнялись. Boto3/R2 tested fake client, SQL — настоящий isolated PGlite с pg_trgm.
