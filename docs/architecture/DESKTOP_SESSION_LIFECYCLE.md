# D1b: предварительные условия безопасности сессии Desktop

Статус: самостоятельная prerequisite-ветка для review Claude L0, 03.11.2026.
Основание: принятый ADR `OBYEKT_PAKET_OFFLINE_DESKTOP_V1.md`, разделы 1.4, 2, 4–5,
и Desktop lane в `KOORDINATSIYA.md` от 03.11.2026. Этот контракт ограничивает
текущий D1b; полный офлайн-сценарий ADR остаётся будущей работой.

## Граница реализации

Реализованы изолированный `OmborSessiya`, защищённый opt-in loader и ограничения
трёх native-команд. Подключения к `useT2Daraxt`, auth, middleware и bootstrap нет.
Обычный reader при выключенном флаге остаётся прежним и не вызывает менеджер.
Даже зависшая очистка старого кэша не блокирует этот обычный reader.

Это не full hook, не готовый Desktop/офлайн-продукт и не подтверждение доступа
реального пользователя. D7/offline lease, постоянное восстановление ключа,
серверный auth-adapter и серверные права этой веткой не реализуются.

## Онлайн-доступ к конкретному объекту

`ObyektRuxsatPort` внедряется доверенным интегратором. При КАЖДОМ открытии он
обязан выполнить текущую онлайн-проверку всей области пакета и вернуть точные
`kompaniyaId`, `foydalanuvchiId`, `obyektId`. Actor определяется серверной сессией;
переданные клиентом идентификаторы — ожидаемая область, не доказательство прав.
Порт нельзя реализовать через локальный boolean `paketRuxsat`, userpermission,
кэш членства или неподтверждённый lease. Подходящий серверный адаптер здесь
не придуман: его подключение и проверка остаются за L0.

До успешной проверки нельзя читать ни память `ObyektOmbor`, ни IndexedDB.
`oqish.ts` получает только ограниченный handle с проверкой поколения на каждой
операции. Сырой параметр `ombor` сохранён для совместимости и очистки, но loader
не читает и не заполняет его. Если `sessiya` вообще не передана, opt-in loader
читает только сервер; локальный кэш не используется.

Отказ 401, истёкшая/закрытая сессия, ошибка сети, неправильная область или поздний
ответ не открывают кэш. 401 не запускает legacy fallback. Ошибки 0/503 закрывают
кэш; автоматического офлайн-разрешения нет.

### 403 и ADR §1.4

403 проверки полного пакета либо самого пакетного запроса может означать
отсутствие `f2.read`/`narx.read` при разрешённом `smeta.read`. Менеджер немедленно
закрывает кэш, очищает отображаемые данные через `bekor` и выдаёт только билет
для результата ОДНОГО текущего legacy-запроса. `port.eski` заново проверяет права
на сервере; сам билет прав не предоставляет и кэш не открывает.

Типизированный отказ `SessiyaRuxsat` содержит status и при 403 — `eskiJoriy`.
После ответа legacy loader проверяет билет и внешний `t.joriy()`. Logout,
refresh, смена пользователя/компании, новое открытие или TTL делают билет
недействительным. При отказе legacy сервера строки не публикуются и не
подменяются кэшем/пустым «успешным» результатом.

## Ключ и жизненный цикл

1. После подтверждённого онлайн-login вызывается `boshlash(scope, tugaydi)`.
   Срок в миллисекундах Unix берётся из доверенной серверной сессии; вызов сам
   по себе не авторизует ни одного объекта.
2. Сначала синхронно инвалидируются старые запросы, handles, память и UI.
   Очистка диска ожидает завершения всех старых записей; новая сессия не создаёт
   кэш до окончания этой очистки. При зависании кэш остаётся закрытым.
3. Создаётся `crypto.subtle.generateKey({name:'AES-GCM', length:256}, false,
   ['encrypt','decrypt'])`. Ключ non-extractable, только в памяти процесса.
   Экспорт, импорт, запись в IDB/localStorage/Credential Manager отсутствуют.
4. Любой refresh и switch повторяют полный цикл с новым ключом. Старый ключ
   не восстанавливается из токена. Перезапуск приложения не открывает старый
   ciphertext новым ключом и требует онлайн-проверки. Переносимая/offline-сессия
   не имитируется.
5. Logout, revoke и истечение TTL вызывают `yop()`: поколение меняется, память
   очищается и обязательный callback `bekor` синхронно убирает строки из UI.
   Не следует ожидать дисковую очистку перед очисткой UI. Все продолжающиеся
   операции проверяют поколение; delayed write удаляется до следующего старта.
6. TTL проверяется таймером и при использовании handle. Одновременно действуют
   абсолютный срок и монотонный дедлайн, поэтому перевод часов назад не
   продлевает активный доступ. Билет fallback ограничен тем же сроком.
7. Ошибка очистки выставляет `tozalashXatosi`; после `await yop()` она доступна
   интегратору. Менеджер после такой ошибки не запускает новый кэш. Ошибка quota
   при обычной записи не отменяет уже полученный серверный результат.

`bekor` должен быть синхронным callback очистки UI без исключений. Внешний
`t.joriy` обязан отражать поколение выбора экрана. При внутреннем сбросе кэша по
403 `bekor` очищает строки, не меняя сам выбор экрана: это сохраняет возможность
авторизованного legacy-ответа. Logout/switch меняют поколение выбора отдельно.
Будущее auth-подключение должно
вызывать `yop` на logout/revoke/switch, а не только переставать рендерить hook.
Ссылки на закрытые handles могут жить до GC; гарантии физического обнуления
памяти JavaScript нет. Non-extractable ключ не защищает от скомпрометированного
доверенного JS, использующего уже открытые данные.

## Native-команды: ACL и runtime-проверка

По [официальной документации Tauri](https://v2.tauri.app/security/capabilities/)
app-команды по умолчанию доступны зарегистрированным webview, пока не включён
app manifest. Поэтому `build.rs` явно перечисляет все три команды через
[`AppManifest::commands`](https://docs.rs/tauri-build/latest/tauri_build/struct.AppManifest.html#method.commands).
Permission `session-local` разрешает именно их; capability `main-local` имеет
`local:true`, окно/webview `main` и не содержит `remote.urls` или wildcard.
Автоматически сгенерированные три TOML permission-файла также входят в ветку.

Каждая команда до обращения к credential проверяет фактический URL webview,
его label и label окна. Разрешены только `main`/`main` и точный Windows origin
`http://tauri.localhost` без другого порта или userinfo. Remote HTTPS,
dev-server, другой webview и поддомены отвергаются. Ни URL, ни caller identity
не принимаются параметрами JavaScript. Доступен один фиксированный credential
этого приложения; выбрать произвольные service/account или читать другие
учётные данные невозможно.

### Новый IPC-контракт; bootstrap ещё не подключён

- `sessiya_token_ol()` возвращает `[token|null, davr]`.
- `sessiya_token_saqla({token, tugaydiMs, davr})` принимает TTL в Unix ms и билет
  из предыдущего чтения. `webview` внедряется Tauri, не передаётся клиентом.
- `sessiya_token_ochir()` инвалидирует билеты и удаляет фиксированный credential.

Интегратор захватывает `davr` ДО асинхронного login/refresh, не после его ответа.
Каждая запись потребляет билет; logout инвалидирует его до Credential Manager
IO. Поздняя запись со старым билетом получает `DESKTOP_SESSION_STALE`. Все
операции сериализованы mutex; неудачная запись/очистка оставляет чтение закрытым
в текущем процессе. Новый login требует нового билета и нового серверного ответа.
Сначала следует синхронно закрыть JS-менеджер, затем ожидать native logout.

Credential хранит версионированную оболочку TTL; просроченный, повреждённый или
старый неверсионированный credential не возвращается и удаляется при чтении.
Native TTL проверяется при чтении/записи, отдельного native-таймера нет.
Срок, токен и process-local билет не доказывают серверное право и не образуют
офлайн-lease. Валидация токена и revoke на сервере обязательны при каждом
авторизующем запросе; перезапуск процесса не восстанавливает JS-ключ/права.

## Что должен проверить интегратор перед подключением

Нужны review L0, настоящий per-object online authorizer, auth/logout/revoke
подключение callback, адаптация IPC нового формата, проверка окна установленного
приложения и полный интеграционный suite. В этой ветке нет production/external
session writes, пользовательских секретов или owner smoke. Native unit tests
работают без Credential Manager IO; frontend tests генерируют только
синтетические ephemeral ключи.
