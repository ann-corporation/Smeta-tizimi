## Round 2 (branch claude/android-qa-2)

Done: O1 (native Material so'rovi), O2 (Forma 3 golden test; server mode already existed), O4 (Rahbar KPI preview), light-theme check, synthetic 26k-row packet for performance.

Not done: **per-node sums in the packet (QQS bilan / ustamali QQS siz / ustamasiz for smeta, fakt and F-2 per RZ/BL)**. Design for the next round: new GET `/api/obyekt-tugun-summa?obyekt_id=` (same gate as `obyekt-paket`; add to `SCOPED_APIS`, `MOBIL_PATH`/`handlers` in `mobil/bff.ts`, `requestPermission` = smeta.read) that reads `daraxtToliqOl` + `ustamaManbaOl` (already used by `/api/hujjat-yarat`), groups descendant rs/mat rows per RZ/BL with `kesimYigish` and runs `ustamaliHisobla` / `obyektSmetaKOplate` from `src/lib/ustamali-summa.ts`, returning `{node_id: {smeta|fakt|f2: {qqs_bilan, ustamali, ustamasiz}}}` with null for unknown; golden test against the web helpers. It is deliberately not in the streamed packet function (free-tier CPU limit, no JSON parsing there). The app then only displays the numbers.

Server checks this round: `tsc -p tsconfig.functions.json` clean, `site-map --check` clean, vitest (hujjat-yarat, hujjat-yarat-oylik, hujjat-yarat-forma3, mobil-bff, _shared) 467 passed.
