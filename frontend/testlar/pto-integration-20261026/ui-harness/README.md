# Изолированный визуальный стенд PTO

Запуск из папки frontend:

```powershell
npx vite --config testlar/pto-integration-20261026/ui-harness/vite.config.ts
```

Откройте http://127.0.0.1:5194/admin/fakt?obyekt=801 и выберите синтетическую компанию. Стенд использует настоящие App/main и компоненты страниц. Постоянный красный баннер указывает, что данные придуманы для QA.

Сервер слушает только 127.0.0.1, не читает .env проекта и не использует proxy или live fallback. Неизвестные API, таблицы и RPC возвращают 404; запись — 403.

Локальные GET для управления стендом; после изменения перезагрузите страницу:

- `/__qa/role?role=pto|bugalter|superadmin` — синтетическая роль.
- `/__qa/size?works=1000` — один раздел и 1000 работ, у каждой два материала и одна машина: 4001 строка дерева, 4000 состояний, уникальные ID.
- `/__qa/size` — исходный малый набор: работа 120/100, работа 1.8/10 и три ресурса.
- `/__qa/markup?mode=known` — явно заданные нулевые коэффициенты: 11 ключей в ответе obyekt_nakrutka_v1 и полный пустой список podval.
- `/__qa/markup?mode=unknown` — отсутствие ответа о накрутке; режим по умолчанию.

Known не означает, что реальные надбавки равны нулю. Ответы отфильтрованы по синтетическим object801/company701; другой контекст пустой. Все названия и количества придуманы. Генерация и HTTP200 не доказывают производительность, авторизацию или корректность БД. Браузерные сценарии и число смонтированных строк фиксируются отдельно; реальная запись в этом стенде не проверяется.

Логические тесты окна:

```powershell
npx vitest run --config testlar/pto-integration-20261026/journal-window.config.ts --maxWorkers=1
```

Они используют контролируемое окно и проверяют порядок фокуса и сохранение draft payload. Физическую прокрутку и browser performance они не доказывают. Файл .test.tsx также подхватывается общим suite.
